# Сервис согласований

Веб-сервис для отслеживания документов и тендерных решений. Приложение работает на Node.js/Express, хранит данные в PostgreSQL Neon и может разворачиваться на Render из GitHub.

## Что добавлено

- две вкладки: «Документы» и «Тендерные решения»;
- отметка «Документ на 2027 год» вместо «В МКТ»;
- отдельные карточки тендерных решений без привязки к месяцам;
- автоматический маршрут согласования в зависимости от лимита;
- ручной переход между этапами;
- отдельные отметки Юли и Ивана;
- срок текущего этапа — 7 дней с возможностью изменить дату;
- красная подсветка просроченного текущего этапа;
- отметка «Готово» и фильтр готовых решений;
- поиск тендерных решений по названию;
- несколько поставщиков с подсказками из общего справочника;
- безопасное расширение существующей базы без удаления документов.

## Как обновить GitHub

Загрузите содержимое этой папки в корень существующего репозитория с заменой старых файлов:

- замените `README.md`, `render.yaml`, `src/server.js` и `public/index.html`;
- добавьте новые файлы `public/styles.css` и `public/app.js`;
- `package.json` можно заменить приложенным файлом — зависимости не изменились.

После коммита Render должен автоматически начать новую сборку, если автодеплой для репозитория включён.

## Подключение к существующей базе Neon

Приложение использует переменную окружения `DATABASE_URL`. В Render она должна содержать текущую строку подключения к вашей базе Neon.

`render.yaml` не создаёт новую базу, не содержит пароль и намеренно не переопределяет `DATABASE_URL`. Значение, уже сохранённое в настройках существующего сервиса Render, не нужно менять.

При первом запуске новой версии приложение выполняет только безопасные операции:

- сохраняет таблицу `documents`;
- добавляет в неё поле `target_year`, если его ещё нет;
- создаёт новую таблицу `tender_decisions`, если её ещё нет;
- сохраняет общий справочник `suppliers`.

Команды удаления таблиц или существующих данных в коде отсутствуют. Документы и тендерные решения хранятся в одной базе Neon, но в разных таблицах.

Перед первым обновлением рекомендуется сделать резервную точку или ветку базы в панели Neon. Это дополнительная страховка перед любым обновлением production-сервиса.

## Проверка после деплоя

1. Откройте в браузере `https://ВАШ-САЙТ.onrender.com/api/health`.
2. Ответ `{"ok":true}` означает, что Render подключился к Neon.
3. Откройте основную страницу и убедитесь, что прежние документы отображаются.
4. Создайте одно тестовое тендерное решение.
5. Перезагрузите страницу и проверьте, что оно сохранилось.

## Локальный запуск

Требуются Node.js 18+ и доступ к PostgreSQL.

```powershell
$env:DATABASE_URL = "строка подключения PostgreSQL"
npm install
npm start
```

Сервис будет доступен по адресу `http://localhost:3000`.
